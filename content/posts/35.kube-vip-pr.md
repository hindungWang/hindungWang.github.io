## 摘要

kube-vip 在 **IPv6-only + 双 ToR 上行** 的节点上（默认路由是 ECMP multipath），如果没有手动指定 `--interface`，Pod 会反复 CrashLoopBackOff，报错 `Found default route but could not determine interface`。

**根因**：multipath 默认路由在 `netlink` 里是一个只有 `MultiPath` 字段（nexthop 数组）、顶层 `LinkIndex = 0` 的 Route；kube-vip 只看顶层 `LinkIndex`，于是误判为"找不到接口"。

**修复**：探测到 `LinkIndex <= 0` 且存在 `MultiPath` 时，取第一个合法的 nexthop 的 `LinkIndex` 作为绑定接口。合并方式为把逻辑重构为按地址族探测、优先 IPv4、失败再试 IPv6，并用 `RouteListFiltered` 只捞默认路由提升效率。

## 背景

问题出自我当时自建的 IPv6-only 环境：单网卡 VM（`ens3`），Calico + BGP，两个 TOR 交换机同时通告 `::/0`。kube-vip 走"自动探测默认网关接口"路径时直接崩溃。

核心排查代码：

```go
# ip -j -6 route show ::/0
[{"dst":"default","protocol":"static","metric":1024,"flags":[],
  "nexthops":[
    {"gateway":"2242::192:168:242:254","dev":"ens3","weight":1,"flags":[]},
    {"gateway":"fe80::aaaa:bbbb:cccc:dddd","dev":"ens3","weight":1,"flags":[]}
  ]}]
```

默认路由是**一条逻辑路由**（`RTA_MULTIPATH`），带两个 nexthop。

## 根因分析

`pkg/vip/util.go` 里的 `GetDefaultGatewayInterface` 逻辑如下：

```go
routes, err := netlink.RouteList(nil, syscall.AF_INET)   // 拉一次 IPv4
routes6, err := netlink.RouteList(nil, syscall.AF_INET6) // 再拉一次 IPv6
routes = append(routes, routes6...)

for _, route := range routes {
    if route.Dst == nil || route.Dst.String() == "0.0.0.0/0" || route.Dst.String() == "::/0" {
        if route.LinkIndex <= 0 {
            return nil, errors.New("Found default route but could not determine interface")
        }
        return net.InterfaceByIndex(route.LinkIndex)
    }
}
```

问题就在这：

1. 对 multipath 路由，`vishvananda/netlink` 返回**一条** `Route`，但顶层 `LinkIndex` 是 0，真正的出口在 `route.MultiPath` 里每个 nexthop 的 `LinkIndex`；
2. 原代码遇到 `LinkIndex <= 0` 直接 return error，于是 ECMP 环境必然失败；
3. 手动指定 `--interface ens3` 能绕过，是因为那条路径根本不调用 `GetDefaultGatewayInterface`（问题被掩盖了）。

## 修复方案

### 第一版：处理 MultiPath 取 nexthop

```go
idx := route.LinkIndex
if idx <= 0 && len(route.MultiPath) > 0 {
    for _, nh := range route.MultiPath {
        if nh.LinkIndex > 0 {
            idx = nh.LinkIndex
            break
        }
    }
}
if idx <= 0 {
    continue
}
return net.InterfaceByIndex(idx)
```

这是问题本身的解药，但 maintainer `Cellebyte` 在 review 里指出了更深的问题，我按意见演进成下面 5 条。

### 顺着 review 演进

**意见 1（性能）**：原来每次都会把 IPv4 + IPv6 的路由表**全部**拉出来再拼接，在大路由表上很低效。

**意见 2（先试 IPv4）**：绝大多数环境默认路由是 IPv4，应该先查 IPv4、命中就返回，不需要再查 IPv6（用早期 return 避免长循环 / 无谓的 IPv6 查询）。

**意见 3（代码组织）**：嵌入的闭包 `findDefault` 拆成独立函数 `getDefaultRoute(family)`。

**意见 4（错误处理）**：不要用 `errors.New("...")` 吞掉底层错误，要 `fmt.Errorf("listing routes: %w", err)` 包裹；两个地址族都找不到时，把两者的错误合并 wrap 返回。

**意见 5（细节）**：`net.InterfaceByIndex(idx)` 丢了 error 返回值，应写成 `return net.InterfaceByIndex(idx), nil`；注释笔误也一并修正。

## 最终代码

```go
// GetDefaultGatewayInterface return default gateway interface link
func GetDefaultGatewayInterface() (iface *net.Interface, err error) {
	// Attempt IPv4 first (usually the default)
	if iface, err = getDefaultRoute(syscall.AF_INET); err == nil {
		return iface, nil
	}

	// If the IPv4 default route is not found, then attempt IPv6 default route.
	if iface, err = getDefaultRoute(syscall.AF_INET6); err == nil {
		return iface, nil
	}

	return nil, fmt.Errorf("unable to find interface with default route: %w", err)
}

// getDefaultRoute attempts to find the default route for the specified address family.
func getDefaultRoute(family int) (*net.Interface, error) {
	// only search for default routes
	filter := &netlink.Route{Dst: nil}
	mask := netlink.RT_FILTER_DST

	routes, err := netlink.RouteListFiltered(family, filter, mask)
	if err != nil {
		return nil, fmt.Errorf("listing routes: %w", err)
	}

	for _, route := range routes {
		// double check
		if route.Dst != nil && route.Dst.String() != "0.0.0.0/0" && route.Dst.String() != "::/0" {
			continue
		}

		idx := route.LinkIndex

		// handle MultiPath
		if idx <= 0 && len(route.MultiPath) > 0 {
			for _, nh := range route.MultiPath {
				if nh.LinkIndex > 0 {
					idx = nh.LinkIndex
					break
				}
			}
		}

		if idx > 0 {
			return net.InterfaceByIndex(idx)
		}
	}
	return nil, errors.New("default route not found")
}
```

改动集中在一个文件 `pkg/vip/util.go`：**+39 / -14**，只影响 `GetDefaultGatewayInterface` 一条路径，向后兼容单 nexthop 环境。

## 过程中学到的东西

1. **`netlink` 对 multipath 路由的表示**：顶层 `LinkIndex=0` + `MultiPath`（nexthop) 数组是绕不开的坑，遇到"明明有默认路由却拿不到接口"先查这两个字段。
2. **跟 maintainer 协作**：review 意见大多是"能不能再高效/再规范一点"，要顺着思路重构成更通用的写法（拆函数、IPv4-first、`%w` 包裹错误），而不是只修自己那个 bug。
3. **`%w` error wrapping**：open-source 项目普遍要求保留错误链，`errors.New` 吞错误会被打回。
4. **force-push 反复 rebase**：Review 过程中 reviewer 误推了一个 commit 到我的分支，让我 `remove last commit and force push again`，这也是开源协作的常态——PR 分支本来就是可重写的，提交历史最终会被 squash 成一条 merge commit。
