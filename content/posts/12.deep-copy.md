## 题目

实现如下结构体的深拷贝。

```go
type Node struct {
	Data int
	Fields []*Node
}
```

即指针指向的内存也需要Copy一份。


## 解析

观察结构体，由于Fields字段里存放的是指向Node结构体的指针切片，深拷贝时要考虑循环引用的问题，如：
```go
struct a :
  data: 1
  fields: b, c
struct b:
  data: 2
  fields: c
struct c:
  data: 3
  fields: a  // 这里循环引用了a， c->a->b, c->a
```

可以考虑使用`map[*Node]*Node`来判断是否有环的情况，即用`map[src] = dst`来保存拷贝过的节点。

## 代码

代码如下：
```go
package main

import (
	"go/ast"
	"go/token"
)

type Node struct {
	Data int
	Fields []*Node
}

// deep copy
var M map[*Node]*Node
func Dup(src *Node) *Node {
	if src == nil {
		return nil
	}
	node := &Node{
		Data: src.Data,
		Fields: nil,
	}
	M[src] = node
	fields := []*Node{}//make([]*Node, len(src.Fields))
	for i:=0;i<len(src.Fields);i++ {
		var tmp *Node
		if src.Fields[i] != nil {
			// if exist, is loop
			if addr, ok := M[src.Fields[i]]; ok {
				tmp = addr
			} else {
				tmp = Dup(src.Fields[i])
			}
		}
		if tmp != nil {
			fields = append(fields, tmp)
		}
	}
	node.Fields = fields
	return node
}

func main()  {
	M = make(map[*Node]*Node)

	a1 := &Node{
		Data:   1,
		Fields: nil,
	}
	a2 := &Node{
		Data:   2,
		Fields: nil,
	}
	a3 := &Node{
		Data:   3,
		Fields: []*Node{a1, a2},
	}
	a1.Fields = append(a1.Fields, a3)
	da3 := Dup(a3)
    // print ast tree
	_ = ast.Print(token.NewFileSet(),a3)
	_ = ast.Print(token.NewFileSet(),da3)
}
```

## 这个算法的问题

核心思路（`map[*Node]*Node` 记忆化）是对的，环和共享引用都能正确处理，但代码本身有三个问题：

### 问题一：nil 元素会被丢弃

`Fields` 中值为 `nil` 的槽位会被 `if tmp != nil { fields = append(fields, tmp) }` 直接过滤掉，导致拷贝后的切片长度变短、下标错位。实测 `src len=4, dst len=2`，语义被破坏。代码里 `//make([]*Node, len(src.Fields))` 那行注释其实已经把正确解法写在旁边了。

### 问题二：全局 map 的脏数据风险

`M` 是包级变量，每次调用前必须手动 `make`；一旦忘记初始化，或者同一个 map 被连续用于两次 `Dup` 调用，上一次调用留下的映射就会污染下一次拷贝。另外 `Dup` 顶部没有查 `M[src]`，对已经拷贝过的源不会复用已有结果。

### 问题三：递归深度

深层链表（几万层）会直接栈溢出，这个问题在深拷贝的递归写法里普遍存在。

## 优化方向

### 方向一：保留 nil 槽位 + map 局部化

两个问题一起修：预分配切片按槽位赋值（不丢 nil），map 在 `Dup` 内部创建（无全局脏数据）：

```go
// deep copy
func Dup(src *Node) *Node {
	return dup(src, make(map[*Node]*Node))
}

func dup(src *Node, M map[*Node]*Node) *Node {
	if src == nil {
		return nil
	}
	node := &Node{Data: src.Data}
	M[src] = node
	fields := make([]*Node, len(src.Fields)) // 预分配，保留 nil 槽位
	for i := range src.Fields {
		if src.Fields[i] == nil {
			continue
		}
		if addr, ok := M[src.Fields[i]]; ok { // 环或共享引用，直接复用
			fields[i] = addr
		} else {
			fields[i] = dup(src.Fields[i], M)
		}
	}
	node.Fields = fields
	return node
}
```

### 方向二：迭代化，避免栈溢出

把递归改成显式栈的迭代写法，深链也能平稳跑完：

```go
func DupIter(src *Node) *Node {
	if src == nil {
		return nil
	}
	M := map[*Node]*Node{src: {Data: src.Data}}
	stack := []*Node{src}
	for len(stack) > 0 {
		s := stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		d := M[s]
		d.Fields = make([]*Node, len(s.Fields))
		for i := range s.Fields {
			if s.Fields[i] == nil {
				continue
			}
			if dd, ok := M[s.Fields[i]]; ok {
				d.Fields[i] = dd
			} else {
				nd := &Node{Data: s.Fields[i].Data}
				M[s.Fields[i]] = nd
				d.Fields[i] = nd
				stack = append(stack, s.Fields[i])
			}
		}
	}
	return M[src]
}
```

实测 1 万层纯链也能顺利完成，且环、共享引用、nil 槽位的行为都与修正版一致。

### 方向三：泛化到任意类型

对于任意含环的数据结构，可以把 `map[*Node]*Node` 换成 `map[unsafe.Pointer]reflect.Value`，用反射写一个通用的记忆化深拷贝。序列化类的库都不行——见下一节。

## 其他方法为什么不行

- **JSON** (`encoding/json`)：遇环直接报 `encountered a cycle` 错误，无法完成。
- **gob** (`encoding/gob`)：看起来能处理共享指针，但实测对环会**无限递归直接栈溢出**（Go 1.22 验证），不可用。
- **反射库**（如 `mohae/deepcopy`）：同样不处理环，遇到时也是递归爆栈。

所以对含环结构，`map` 记忆化这条路是绕不开的。

## 对比 k8s 的 deepcopy-gen

Kubernetes 用 `k8s.io/code-generator` 自动生成 `zz_generated.deepcopy.go`，每个类型生成 `DeepCopyInto(out *T)` 与 `DeepCopy() *T` 两个方法。有意思的是：**它完全不做循环引用处理**，靠的是约定而不是算法。

生成的模式是纯递归，没有任何记忆化：

```go
// *out = *in 先整体浅拷贝
func (in *Affinity) DeepCopyInto(out *Affinity) {
	*out = *in
	if in.NodeAffinity != nil {          // 指针字段：新建 + 递归
		in, out := &in.NodeAffinity, &out.NodeAffinity
		*out = new(NodeAffinity)
		(*in).DeepCopyInto(*out)
	}
	return
}
```

对指针切片（对应本例的 `Fields []*Node`）生成的是：

```go
if in.Fields != nil {
	in, out := &in.Fields, &out.Fields
	*out = make([]*Node, len(*in))       // 预分配，按槽位赋值
	for i := range *in {
		if (*in)[i] != nil {              // 显式判空，nil 槽位被保留
			(*out)[i] = new(Node)
			(*in)[i].DeepCopyInto((*out)[i])
		}
	}
}
```

为什么不需要防环？因为 **k8s API 对象被约定为树 / DAG，禁止指针环**——需要引用别的对象的字段（如 `ObjectReference`、`SecretReference`）存的都是 name 这类字符串而非指针，物理上无法成环。反过来看：

- 若真喂一个环进去，`DeepCopyInto` 会无限递归直接爆栈；
- **共享引用也不保留**：同一节点被多个字段引用时会被重复复制成两份（k8s 的语义里这没有问题，`DeepCopy()` 本就要做隔离）。

对比总结：

| | 本文算法 | k8s deepcopy-gen |
|---|---|---|
| 环检测 | map 记忆化 | 无（约定无环） |
| 共享引用 | 保留（复用同一份拷贝） | 不保留（重复复制） |
| nil 槽位 | 原版丢失 / 修正版保留 | 保留（按槽位赋值） |
| 拷贝方式 | 运行时递归 / 迭代 | 静态生成代码，零反射开销 |

顺带一提：k8s 生成器 `make(len)` 预分配 + 显式判空、按槽位赋值的写法，恰好就是本文「优化方向一」的处理方式——这也是深拷贝这一类题里最容易踩的坑。
